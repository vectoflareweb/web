本项目采用 **5 层架构**设计，产品层与框架层完全解耦。前端使用 **TanStack Start**（基于文件的路由），后端依赖 **Cloudflare Workers** 边缘节点，并使用垂直特性的项目结构。

## 五层架构

| 层 | 目录 | 职责 |
|---|---|---|
| **Product** | `src/product/` | 品牌字符串、产品数据、AI 提示词、字典 |
| **Site Configuration** | `src/config/` | SITE_ID、域名、locale、功能开关、重定向 |
| **Website Foundation** | `src/features/` + `src/routes/` | 认证、搜索、AI 聊天、SEO、询盘、管理、存储 |
| **Cloudflare Platform** | D1 + KV + R2 + Vectorize + Workers AI | 运行时基础设施 |
| **Infrastructure** | GitHub Actions CI/CD + CDN | 部署流水线 |

框架代码从不直接引用品牌数据——统一从 `@/config/` 读取（底层重新导出自 `@/product/`）。
要部署新产品，只需替换 Product 层和 Config 层。

## 设计哲学

### 1. 产品层与框架层分离
品牌数据集中在 `src/product/`，框架代码通过 `@/config/` 读取。部署新产品时,
只需替换 Product 层和 Config 层——框架代码无需修改。

### 2. 垂直特性切片 (`src/features/*`)
我们不推荐按照文件类型（如全部的 actions 放一个文件夹，全部的 components 放另一个）来组织代码，而是按照**业务功能 (Feature)** 来组织。
比如 `src/features/feedback/` 目录下会包含与反馈相关的：
- 数据库 Schema (`feedback.schema.ts`)
- 服务端操作 (`feedback.server.ts`)
- 前端组件 (`FeedbackForm.tsx`)

这样修改反馈逻辑时，你只需要在这个目录中工作，实现了高内聚低耦合。

### 3. 文件路由 (`src/routes/*`)
我们使用 **TanStack Router** 进行基于文件的路由映射。
- `src/routes/api/*` 用于定义供外部调用的标准 RESTful API 接口。
- 绝大多数页面被放置在 `{-$locale}/` 组内，以便开箱即用支持多语言。

### 4. 环境隔离 (`@/lib/env`)
所有环境变量的读取**必须**通过 `@/lib/env` 进行。我们通过 Zod 校验了环境变量的完整性，这样在部署出错时能第一时间获得报错，而不是在运行时崩溃。
